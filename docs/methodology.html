Honesty table

What’s real, what’s simplified and disclosed, and what isn’t built yet. Plain statements, checkable in the code itself, not buried in comments.

Real
ERC-8004 registry reads
Calls the actual Identity and Reputation registries live on Monad mainnet. Function signatures pulled from the reference contracts, not the spec doc.
Funding-provenance signal
Reads real transfer events on Monad, verified against real wallets and real transactions. One caveat stated plainly, because the raw numbers are easy to misread: the circular-funding and fan-out checks run over AUSD, and no reviewer wallet on this registry has ever moved AUSD. So their hit counts describe unrelated token traffic, not agent reputation, and they are not evidence about any agent. The checks that actually apply to reviewers are the native-MON provenance ones listed above.
Shared funding origin
Records who paid into each wallet, then checks whether wallets that present as separate parties were capitalised by the same payer. Both native and token funding are followed, because an ERC-20 transfer’s transaction recipient is the token contract rather than the wallet, so token funding is invisible to a native-only scan. Gas top-ups are excluded from the verdict: the earliest payment into a wallet is often a small fee subsidy rather than whoever actually funded it, and treating those as the same relationship produces a confident wrong answer. Both of those corrections are carried over from an earlier project where each was caught against live data. Known limit: native value moved by an internal contract call does not appear in top-level transactions, so some funding routes remain invisible.
Wallets created together
Looks up when each reviewer wallet first appeared on chain in any transaction, then checks whether an agent’s reviewers share a creation window. Needs three or more inside a day: two wallets born near each other is a coincidence that will happen constantly across thousands of reviewers, but a batch is not. The verdict is reached against each agent’s own reviewer set rather than stored per wallet, since the same wallet can sit in a tight cluster for one agent and a loose spread for another. Wallets whose creation date could not be resolved are left out rather than treated as born at block zero, which would make every unknown wallet cluster with all the others.
Shared funding source
Catches one wallet quietly bankrolling several different reviewers, the case the other two funding checks miss: circular funding needs money flowing back, and fan-out only fires at 15 or more recipients. Because exchanges pay reviewers incidentally among thousands of others, any funder already shaped like a payment processor is recorded but not flagged. That exclusion uses the indexer’s own fan-out result rather than an outside label service, so it keeps working regardless of third-party availability.
Automated review timing
Measures how ragged the gaps are between a wallet’s consecutive reviews of one agent. People review at irregular intervals, minutes then hours then days; a script does not. The measure is the coefficient of variation, which is scale-free, so it catches a bot firing every 50 seconds and one firing every 50 minutes alike. It only fires on 5 or more intervals, so a short uniform run is not enough. Zero-second gaps from reviews sharing a block are excluded, since counting them would manufacture a perfect score. Scoring is per agent after an earlier version measured whole histories and missed three of four scripted wallets: a burst on one agent was separated from the next by a long pause, and averaging those pauses in hid the regularity inside each burst.
Deep per-wallet funding history
A live index only covers a recent window, which a patient funder could simply pay around: the money arrives long before the wallet ever reviews anything and becomes worth watching. So the first time a wallet appears as a reviewer, its full history is pulled on demand, back to its very first transaction. An earlier version did this for AUSD as well, and it was removed once measured: it returned nothing across 4,476 reviewers, because reviewers here do not hold AUSD, while consuming roughly half of all indexing time.

Simplified, disclosed not hidden
Token coverage
This page previously said AUSD was “the stablecoin real agents use to pay each other on Monad today”. That was wrong, and it was never checked before being published. Measured on 2026-09-21: across 4,476 reviewer wallets the AUSD trace returned zero results, and querying transfer history directly for individual reviewers, including the most active ones in the flagged cluster, returned zero transfers each. Reviewers on this registry do not use AUSD at all. The funding that matters here moves in native MON, which is what the provenance checks above now follow. Submitting a review costs nothing but gas, so there is no payment attached to a review to trace in the first place.
Not built yet
Wallet reputation labels
Previously described here as working. It is not. The code path exists but points at an endpoint that returns 404, and no API key is configured, so not a single wallet has ever been screened against exchange or institutional labels. The lookup page now reports this as NOT ACTIVE rather than showing an empty result as if it were a clean pass. Corrected on 2026-09-21 after checking the live table and finding it empty chain-wide.
Agent Wallet hook
The gap it would fill is real and documented, but no code exists for it yet. This is what would make Headwater infrastructure other apps call, not a standalone checker.
Registering Headwater as a listed agent
Requires a funded wallet and a live on-chain transaction. Not registered yet.
